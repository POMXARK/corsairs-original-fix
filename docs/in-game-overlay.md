# Счётчик FPS и уведомления внутри оригинальных «Корсаров»: исследование

Для разработчиков, которым нужно понять, как отладочный текст попадает на экран оригинального `ENGINE.exe` (Storm Engine 1, 2000), и повторить приём.

## Задача

Игра работает под Windows 11 через DDrawCompat 0.5.4 (2560x1440). Нужно показывать поверх игры счётчик FPS и надписи «скриншот сохранён» / «запись началась» / «запись сохранена». Положение задаёт `fix\osd.ini`.

## Что не сработало: окна поверх игры

DDrawCompat показывает кадр в слоёном окне с флагом TOPMOST (ex-style `0x808002C`). Любое наше TOPMOST-окно оказывается под ним или видно один кадр: z-порядок не выигрывается, даже если поднимать окно каждую миллисекунду.

| Попытка | Результат |
|---|---|
| Окно с `TopMost`, подъём раз в 100 / 20 / 1 мс | видно ~1 кадр, затем игра перекрывает |
| Безрамочное окно на весь экран (`FullscreenMode=borderless`, `WINDOW_MODE 1`) | не помогло |
| Окно-«владелец» (`GWLP_HWNDPARENT` игры) | игра сворачивается, мышь застревает, белая рамка |
| `SYSTEM_MONITOR` в `engine.ini` | это отладочный экран слоёв/текстур/звуков, а не FPS |

Вывод: рисовать надо не снаружи, а в самом кадре игры, до его показа. Так делают и внутриигровые оверлеи (Steam, RTSS, читы): код оказывается в процессе и перехватывает функцию показа кадра.

## Как нашли точку внутри игры

Источник — декомпиляция `ENGINE.exe` (Ghidra, `ref/pdm-decomp-exe/ENGINE.exe.c`) и дизассемблер `llvm-objdump -d -M intel`.

1. **Рисование текста.** `FUN_0040e860(font, x, y, fmt, ...)` — cdecl, отладочный текст движка. Шрифт — глобальный объект `0x7C77A8`. Игра сама вызывает её в `Realize_Layers` для надписи «STORM ENGINE v…» (адреса 0x420B6B, 0x420BE0), то есть в конце кадра рисовать ею безопасно.
2. **Кадр.** `SERVER::Realize` (`FUN_00420120`) выбирает путь по флагам в `*(0x77dd1c + 0x498c0)`: бит 4 — `Realize_Layers` (`FUN_004205c0`), бит 2 — ядро и `FUN_0040a330` (флип), бит 1 — отладочные экраны.
3. **Первая гипотеза (неверная).** Хук на вызов `FUN_0040a330` по адресу 0x42019E. В логе «frames through the flip 0»: геймплейный кадр идёт не через него.
4. **Верная точка.** Конец `Realize_Layers` — `mov ecx,[0x77dd1c]` / `call FUN_0040a2a0` по адресу **0x420C0A**, байты `E8 91 96 FE FF`. `FUN_0040a2a0` показывает кадр (Flip через vtable+0x2c). До этого вызова поверхность ещё не показана, и текст ложится в кадр. Здесь же `trace.log` каждого кадра показывает цепочку `Execute → Realize → Realize_Layers`, которая подтвердила путь.

## Как устроена вставка кода

Игра 32-битная, не перемещается (база 0x400000), поэтому все адреса — константы. DLL не нужна:

1. `overlay/overlay.c` компилируется clang в машинный код без релокаций и импортов. Все адреса (`0x40E860`, `0x7C77A8`, `0x40A2A0`) заданы числами.
2. `capture.ps1` (класс C# `GameHook`) через `VirtualAllocEx` выделяет страницу RWX по фиксированному адресу `0x7E000000`: данные в начале, код по `0x7E001000`.
3. Он останавливает потоки игры (`SuspendThread`), меняет `rel32` вызова по 0x420C0A так, чтобы он вёл на `0x7E001000`, сбрасывает кэш инструкций и возобновляет потоки. Перед правкой проверяются байты на месте вызова: другой `ENGINE.exe` не патчится.
4. Функция `hook(dev)` (fastcall, как оригинал) увеличивает счётчик кадров, рисует две строки шрифтом движка и вызывает настоящий `FUN_0040a2a0(dev)`.
5. Строки и координаты меняются из `capture.ps1` через `WriteProcessMemory` в страницу данных:

| Смещение | Содержимое |
|---|---|
| +0x00 / +0x04 | x, y счётчика FPS |
| +0x08 / +0x0C | x, y уведомления |
| +0x10 | строка FPS (48 байт, пустая — не рисуется) |
| +0x40 | строка уведомления (64 байта) |
| +0x7C | счётчик кадров через хук |
| +0xC4 / +0xD0 | настоящие `SetCursorPos` / `MoveWindow` |
| +0xC8 / +0xCC | начало окна (client origin) |
| +0xF4 | лимит кадров (fpslimit) |
| +0xF8 | настоящий `GetCursorPos` (для `cursor_get`) |
| +0x900 / +0x904 | смещение клиентской области от внешнего угла окна (рамка, `frame=3`) |
| +0x908 / +0x90C | добавка к ширине/высоте от рамки |

6. Текст включается после 100 кадров через хук, чтобы не рисовать на экранах загрузки. Раз в 5 с в `fps.log` пишется «hook: frames N, game responding …».

## Как нашли причину зависания на загрузке

После установки хука игра проходила ролики и зависала на плашке «загрузка», хотя счётчик кадров показывал 0. Изоляция по режимам `-HookMode`:

| Режим | Что делает | Результат |
|---|---|---|
| `-NoHook` | ничего | работает |
| 1 | выделяет память и пишет код, вызов не патчит | работает |
| 3 | патч вызова без остановки потоков | зависает |
| 4 | вызов идёт через пустой `jmp 0x40A2A0` | работает |
| 5 | перед `jmp` только `inc [счётчик]` | работает, счётчик растёт |
| полный хук | тело `hook()` | зависает |

Вывод: сам патч и данные в порядке, ошибка в коде тела. В `trace.log` движок дописывает стек при исключении в каждом кадре: исключение глоталось, кадр не доходил до показа. Причина — в `overlay.bin` лежало не 126 байт кода, а весь COFF-объект (297 байт): `llvm-objcopy -O binary` для COFF копирует файл целиком. Игра исполняла заголовок. Хук с `jmp` (режимы 4 и 5) работал, потому что его байты писались вручную.

Исправление: `build_overlay.sh` компилирует в ELF (`-target i686-unknown-linux-gnu`), где `-O binary --only-section=.text` отдаёт чистый код, и проверяет отсутствие релокаций.

## Что осталось известным

- F8 в самой игре (клавиша 0x77, `FUN_004264e0`) тоже пишет `shot0000.tga`; `capture.ps1` делает свой снимок, получается два файла.
- Шрифт отладочный, мелкий и только латиница: поэтому тексты уведомлений английские («SCREENSHOT SAVED»).
- Один адрес вставки привязан к конкретной сборке `ENGINE.exe` (md5 `a1e366982382611062f990db7d546dd0`); при другой сборке `Install` откажется патчить и скрипт откатится на окна поверх игры.

## Файлы

- `overlay/overlay.c` — код хука; `move_fix` (0x3000) переносит окно с учётом рамки (`frame=3`); `cursor_get` (0x2000) подменяет `GetCursorPos` в модулях интерфейса, см. [click-input-research.md](click-input-research.md); `build_overlay.sh` — сборка в `overlay.bin`.
- `capture.ps1` — `GameHook` (установка, `Poke`, `Peek`), логика F8/F9/FPS.
- `install.ps1` — копирует `overlay.bin` в `fix\`.
