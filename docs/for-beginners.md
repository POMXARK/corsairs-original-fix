# Как всё это работает: подробно и для новичков

Документ для тех, кто не писал под Windows и не знает, что такое «хук» и «патч». Сначала идея, потом файлы, потом каждая найденная проблема: симптом, причина (с именами функций Windows API), решение. Короткие технические журналы прогонов лежат рядом: [windowed-mode.md](windowed-mode.md), [in-game-overlay.md](in-game-overlay.md), [click-input-research.md](click-input-research.md), [ddrawcompat.md](ddrawcompat.md).

## 1. Что мы вообще делаем

Игра — «Корсары» (Sea Dogs) 2000 года, файл `ENGINE.exe`. Она написана для Windows 98/2000 и ждёт видеорежим 640×480 / 800×600 в 16 цветов. На Windows 11 с современной видеокартой это не работает как есть: цвета лиловые, окно уезжает в угол, нет мыши, нет записи экрана.

Правила проекта:
- **Файлы игры не меняем и не храним.** Нужна ваша лицензионная копия. `ENGINE.exe` на диске остаётся как был.
- **Всё, что добавили, делаем на лету.** Программа-помощник (`capture.ps1`) запускает игру, на время жизни процесса кладёт в его память маленький кусок нашего кода и подменяет несколько вызовов. Закрыли игру — всё исчезло.

Ядро решения из двух частей:
1. **DDrawCompat** — чужая открытая библиотека `ddraw.dll`, которая переводит старую графику DirectDraw на современную. Ставится рядом с `ENGINE.exe`.
2. **Наш «оверлей»** — машинный код (`overlay.bin`, исходник `overlay/overlay.c`) и PowerShell-сценарий (`capture.ps1`), которые управляют окном, мышью, FPS, записью.

## 2. Словарь

| Слово | Что значит |
|---|---|
| **Процесс** | запущенная программа; у игры он один, `ENGINE.exe` |
| **Окно (HWND)** | объект Windows с рамкой, заголовком, областью рисования. «Клиентская область» — внутренняя часть без рамки, где игра рисует |
| **Windows API** | функции системы (`CreateWindowExA`, `MoveWindow`, `GetCursorPos`…), которые программа вызывает из `user32.dll`, `kernel32.dll` |
| **IAT (таблица импорта)** | в `ENGINE.exe` есть список «адресов функций Windows»: когда игра зовёт `MoveWindow`, она на самом деле прыгает по адресу из этого списка. Если подменить адрес — вызовется наш код |
| **Хук / патч** | подмена: либо адрес в IAT, либо несколько байт кода игры (`call` → наш `call`) |
| **Инъекция** | запись нашего кода в память чужого процесса (`VirtualAllocEx` + `WriteProcessMemory`) |
| **Оверлей** | в этом проекте — наш код внутри игры, рисующий счётчик FPS и правящий окно/мышь. Не окно поверх |
| **DDrawCompat** | библиотека `ddraw.dll`, подменяющая старый DirectDraw |
| **MCI** | старый интерфейс Windows для видео; заставки игры (`logo1.avi`, `logo2.avi`) идут через него |
| **WASAPI loopback** | способ «слушать» то, что играют колонки, для записи звука |

Находит игру, качает DDrawCompat 0.5.4 (сумма SHA-256 зашита), кладёт `ddraw.dll` и `DDrawCompat.ini`, правит `engine.ini` (16 бит, размер окна), увеличивает шрифты в `fonts.ini`, копирует рабочие файлы в `<игра>\fix\`, создаёт три ярлыка на рабочем столе. Что копируется в `<игра>\fix\`: `install.ps1, settings.ps1, capture.ps1, overlay.bin, play.ps1, play.vbs, settings.vbs, profile.ps1, DDrawCompat.ini`. После установки папку с репозиторием можно удалить.

## 4. Как это запускается (по шагам)

1. Вы жмёте ярлык «Корсары — игра». Ярлык зовёт `play.vbs`, он просит права администратора (PresentMon, запись в чужую память) и запускает `play.ps1` через `conhost --headless`, чтобы не мигала консоль (7.11).
2. `play.ps1` вызывает `profile.ps1`, потом `capture.ps1 -Launch` (скрытое окно PowerShell).
3. `capture.ps1` создаёт процесс `ENGINE.exe` **приостановленным** (`CreateProcessW` с флагом `CREATE_SUSPENDED`): процесс есть, но ни одна его инструкция не выполнилась.
4. Пока он «заморожен», `capture.ps1`:
   - выделяет в нём память по адресу `0x7E000000` (`VirtualAllocEx`) и записывает туда `overlay.bin` и область данных;
   - в данные пишет размеры рамки и место, где должно быть окно;
   - патчит два вызова в коде игры (см. раздел 6);
   - возобновляет поток (`ResumeThread`).
5. Игра стартует уже с нашими патчами и сразу создаёт окно с рамкой по центру.
6. Дальше `capture.ps1` крутит цикл: подменяет в таблице импорта `MoveWindow` и `SetCursorPos`, следит за окном и курсором, рисует FPS, ловит F8/F9/F10/F11, при необходимости посылает Esc на заставках. Игра закрылась — скрипт завершается.

## 5. Как работает окно

Игра сама создаёт окно один раз в `WinMain`: вызов `CreateWindowExA(0, "Seadogs v 1.0", …, стиль 0x80000000 (WS_POPUP), x=0, y=0, 800, 600, …)`. То есть окно без рамки в углу экрана. Тип окна выбирается в настройках (`frame` в `fix.ini`):

- `0` — как у оригинала, в углу, без рамки;
- `1` — полоса-заголовок отдельным окном, окно по центру;
- `3` — **настоящая рамка Windows** (заголовок, кнопки свернуть/закрыть, системное меню) и окно по центру. Значение по умолчанию.

Как делаем `frame=3`:
1. Стиль окна: `0x00CA0000` = `WS_CAPTION | WS_SYSMENU | WS_MINIMIZEBOX` (без `WS_POPUP`, без изменения размера).
2. **Внешний размер больше игрового.** Игра рисует 800×600, а рамка добавляет по бокам и сверху. Размеры рамки берём из `GetSystemMetrics(SM_CXFIXEDFRAME=7)`, `(SM_CYFIXEDFRAME=8)`, `(SM_CYCAPTION=4)`: на Windows 11 получается 3 пикселя по бокам, 26 сверху, итого окно 806×629 при клиентской области ровно 800×600.
3. Окно создаётся и ставится по центру рабочей области **сразу** подменённым `CreateWindowExA` (`create_fix`), без подгонки потом.
4. Игра уверена, что окно в точке (0,0): ей отдаётся «смещение окна» (`DATA+0xC8/0xCC`), и наши подмены вычитают или прибавляют его (раздел 7).
5. Через 2 секунды `capture.ps1` замеряет настоящую клиентскую область (`GetClientRect`, `ClientToScreen`) и, если она не 800×600, поправляет отступы. На практике поправка не нужна, это страховка.
6. Когда пользователь перетаскивает окно за заголовок, система сама двигает его; скрипт следит за `ClientToScreen` и обновляет смещение. Курсор не зажат (`ClipCursor` снимается), как в окне виртуальной машины: ввод идёт в игру, пока окно в фокусе.

## 6. Как работают патчи

Есть три вида подмены.

**а) Подмена в таблице импорта (IAT).** Адрес `MoveWindow` лежит в ячейке `0x43116C` внутри `ENGINE.exe`, `SetCursorPos` — `0x43119C`, `GetTickCount` — `0x431050`. `capture.ps1` записывает вместо них адреса наших функций (`move_fix`, `cursor_fix`, `fast_tick`), а настоящий адрес сохраняет в области данных, чтобы наша функция могла вызвать оригинал после правки аргументов. Для библиотек интерфейса (`MENU.dll`, `WS_*.dll`, …) то же самое делается с `GetCursorPos`: ячейки ищутся разбором PE-заголовка каждой загруженной DLL.

**б) Подмена вызова в коде.** В приостановленном процессе таблица импорта ещё не заполнена (это делает загрузчик Windows уже после возобновления), поэтому подменять там нечего. Тогда патчится сам код игры: 6 байт `FF 15 <адрес>` («вызвать функцию по адресу из ячейки») заменяются на `E8 <смещение> 90` («вызвать наш код», плюс пустая команда). Так сделаны:
- `0x417BD8`: `CreateWindowExA` → `create_fix` (смещение оверлея `0x4000`);
- `0x417FE4`: `GetWindowRect` для заставок → `rect_fix` (`0x5000`).
Настоящую функцию наш код вызывает через ту же ячейку IAT, к тому времени она уже заполнена.

**в) Подмена кадра.** В конце кадра (в `Realize_Layers`, адрес `0x420C0A`) патчится `call`, чтобы вместо него вызывался `hook()` из оверлея: он считает кадры, рисует счётчик FPS и график, ограничивает FPS, повторяет зажатые клавиши, двигает окно изнутри потока игры. Для рисования используется шрифтовая функция самого движка.

Куда всё кладётся: данные `0x7E000000` (4 КБ и далее, всего `0x8000`), код `0x7E001000`. Карта смещений данных описана в шапке `overlay/overlay.c`. Адрес выбран «пустым»: у 32-битного процесса там ничего нет.

Как мы нашли нужные адреса: декомпилированный текст `ENGINE.exe` (в репозиторий он не входит, файлы игры не храним) и дизассемблер. Вся логика поиска описана в [in-game-overlay.md](in-game-overlay.md).

## 7. Проблемы и как их исправили

### 7.1. Окно в углу, лиловые цвета, пустой список разрешений
Причина: игра 16-битная, использует DirectDraw, а современный драйвер и 32-битный рабочий стол этого не любят. Решение: DDrawCompat + `DesktopColorDepth=16`, `SupportedResolutions`, правка `engine.ini`. Подробно: [ddrawcompat.md](ddrawcompat.md).

### 7.2. Меню не реагирует на мышь, когда окно не в углу
Симптом: нет подсветки кнопок, клик мимо, после клика «мёртвая» клавиатура.
Причина: мышь в `ENGINE.exe` приходит оконными сообщениями (координаты относительно окна), а вот модули интерфейса (`MENU.dll`, `WS_BUTTON.dll`, `MAP.dll` и ещё около 14) сами вызывают `GetCursorPos`. Эта функция даёт координаты **относительно всего экрана**; модули принимали их за игровые, то есть рассчитывали, что окно в (0,0).
Решение: подмена `GetCursorPos` в их таблицах импорта на `cursor_get` (`overlay.c`): настоящий вызов, потом вычитание начала клиентской области. Аналогично `SetCursorPos` → `cursor_fix` прибавляет начало. Проверка: скриншоты (hover, клик «Создатели», Esc).
Ловушка: `Process.Modules` в 64-битном PowerShell не видит 32-битные модули игры. Использован `EnumProcessModulesEx` с фильтром `LIST_MODULES_32BIT`.

### 7.3. Окно двигается рывками, картинка застывает или чёрная
Причины:
1. DDrawCompat рисует кадр в собственном окне поверх игрового. Если двигать окно игры **снаружи** (из другого процесса: `SetWindowPos`), его картинка остаётся на прежнем месте. Решение: двигать окно из потока игры (`hook()` вызывает настоящий `MoveWindow` при флаге `DATA+0xD4`).
2. Смена стиля окна на лету даёт чёрное окно: DDrawCompat рисует в старую область. Решение: `blt_fix` подправляет прямоугольник `Blt` на смещение окна.
3. Игра сама зовёт `MoveWindow(hwnd, 0, 0, 800, 600)` при смене видеорежима, окно прыгало в угол. Решение: `move_fix` добавляет смещение и отступы рамки.
4. Перемещение окна **до** первых игровых кадров не работает: картинка остаётся в углу. Поэтому подгонка ждала кадров; именно эту подгонку убрал `create_fix`.

### 7.4. `AdjustWindowRectEx` обманул (чёрные полосы по краям)
Для расчёта внешнего размера окна по клиентскому есть функция `AdjustWindowRectEx`. В процессе PowerShell она вернула отступы 8 и 31, настоящие у окна игры — 3 и 26 (разные DPI-контексты и темы процессов). Клиентская область получилась 810×610, виднелись чёрные полосы и артефакты.
Решение: брать `GetSystemMetrics` и **измерять** результат (`GetClientRect`), а не верить расчёту.

### 7.5. Курсор зажат и окно плохо тащится
Игра один раз вызывает `ClipCursor(0,0,800,600)`: курсор нельзя вывести за этот прямоугольник. После переноса окна прямоугольник старый, и перетаскивание дёргалось.
Решение: при `frame=3` зажим снимается (`ClipCursor(NULL)`) в главном цикле, пока игра в фокусе. Вне фокуса игра ввод не получает (стандартное поведение Windows), как у любого окна.

### 7.6. Окно возникало в углу первые 5–10 секунд
Скрипт ждал процесс игры (`Get-Process`, опрос каждые 0,5 с), ставил патчи на уже работающей игре, а окно двигать можно только после ~100 кадров (п. 7.3). Решение: запускать игру приостановленной и подменять `CreateWindowExA` до первой инструкции (разделы 4 и 6).
Подвох: у приостановленного процесса IAT не заполнена, поэтому подмена вызова в коде, а не ячейки. Ещё подвох: до возобновления нельзя подменить `MoveWindow` в IAT, поэтому сразу после `ResumeThread` скрипт каждые 2 мс смотрит ячейку и подменяет её, как только загрузчик её заполнил.

### 7.7. Заставки показывались чёрными в окне
Игра проигрывает `logo1.avi` и `logo2.avi` через MCI (`avivideo`), а область видео берёт из `GetWindowRect(окно)`, как будто окно стоит в (0,0), в клиентских координатах. У окна по центру прямоугольник уже в экранных координатах (874,380…), и видео рисовалось за пределами окна.
Решение: подменить именно этот вызов (`0x417FE4`) на `rect_fix`: он возвращает `0,0,800,600`. Другие вызовы `GetWindowRect` в игре не тронуты. Проверка: тест `autotest=6` снимает кадры заставок.

### 7.8. Окно скрипта «умирало молча»
`Log` писал в `fps.log` через `Add-Content`; пока файл читали (по ssh), записи падали с `IOException`, а `$ErrorActionPreference = "Stop"` превращал это в смерть главного цикла без сообщения. Решение: повтор записи и `try/catch` вокруг цикла.
Похожая ловушка: при `Stop` любое сообщение в stderr нативной программы (ffmpeg) считается ошибкой; такие вызовы идут через `cmd /c "… 2>&1"`.
Ещё: `Add-Type` для C# считает предупреждения компилятора ошибками. Неиспользуемое поле или опечатка — и скрипт не стартует, а в окне ничего не видно (скрыт). Проверка: запускать `capture.ps1` без `-WindowStyle Hidden`.
Ещё: `[CapNative]::Windows(pid)` (перечисление окон и их заголовков) вешался, когда окно игры не отвечало (`SendMessage` внутри). Из частого опроса убрали.

### 7.9. Звук видео
Встроенный в сборку ffmpeg не умеет WASAPI, а «стерео-микшера» на ПК нет. Решение: свой `AudioLoop` (C# + COM `IAudioClient`, флаг loopback `0x20000`) пишет звук колонок в файл; при остановке записи ffmpeg склеивает картинку и звук (`-c:v copy -c:a aac`). Для пауз в loopback дописывается тишина. Звук общесистемный: чужие приложения тоже попадут в запись.

### 7.10. Проверка «по хешу картинки» врала
Сначала успех автотеста определялся по изменению хеша экрана. Он менялся от курсора и счётчика FPS, поэтому давал «работает», когда не работало. Теперь критерий — только скриншот и взгляд на него (экран «Создатели», кнопка «Выход» и т. п.).

### 7.11. При запуске мелькало чёрное окно консоли
- **Симптом.** Запуск настроек или игры на долю секунды показывал консоль.
- **Причина 1: `.cmd`.** Батник-файл всегда открывает окно cmd, раньше чем что-то успевает его спрятать. Файлы `settings.cmd`, `play.cmd`, `play-lowlag.cmd` убраны, запускать нужно `.vbs` (ярлыки на них и указывали).
- **Причина 2: `powershell -WindowStyle Hidden`.** PowerShell сначала создаёт видимую консоль и лишь потом прячет её. Поэтому `play.vbs` и `settings.vbs` запускают `conhost.exe --headless powershell.exe …`: консоли нет вообще (нужна Windows 10 1809 или новее).
- **Как проверить.** Запустите ярлык: окно консоли не должно появляться, а `ENGINE.exe` и `powershell.exe` (capture) должны быть в диспетчере задач.

### 7.12. Не решено
- **Вид заголовка окна.** Он рисуется системой в упрощённом стиле (как у Windows 7 Basic). Пробовали `DwmSetWindowAttribute`, `SetWindowTheme`, `SWP_FRAMECHANGED`: без эффекта. Причина не найдена.
- «FPS 0» в счётчике при FPS игры 30 бывает в OSD; причина не выяснена, показания игры (`GAME`) верны.
- Миниатюры сохранений, двойное срабатывание F8, видео 60 к/с.

## 8. Автотесты (для разработчиков)

В `fix.ini` ключ `autotest=N`: игра сама запускает сценарий и закрывается; результат в `fps.log`, скриншоты в `Документы\My Games\Sea Dogs\auto`.

| N | Что проверяет |
|---|---|
| 1 | наведение, клик «Создатели», Esc, ↓×2 |
| 2 | только наведение на кнопку |
| 3 | перетаскивание окна за заголовок |
| 4 | свободный курсор (вне окна) |
| 5 | запись видео 6 с со звуком (`volumedetect`) |
| 6 | заставки (`skipintro=0`): кадры на 3/8/14/20/30 с и один Esc на 4 с |

После теста удалите `autotest` из `fix.ini`, иначе игра закроется сама. Правила: одна гипотеза за прогон, успех по скриншоту, итог в `docs/`.

## 9. Безопасность

- Запись в память чужого процесса может вызвать ложное срабатывание антивируса. В игре 2000 года античита нет. Код открыт, читайте `capture.ps1` и `overlay/overlay.c`.
- Скачивается только DDrawCompat (с проверкой SHA-256), PresentMon 2.6.0 и ffmpeg (по закреплённым ссылкам и суммам) при первом запуске в `fix\tools`.
- Все изменённые файлы игры сохраняются как `.orig`; `install.ps1 -Uninstall` возвращает их.
