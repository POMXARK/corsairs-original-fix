# Исследование: сглаживание (ReShade, dgVoodoo2)

Цель: сглаживание и резкость в оригинальных «Корсарах» (DX7, ddraw) поверх DDrawCompat. Правила: одна гипотеза за прогон, успех — по скриншоту или словам пользователя. Дата начала: 2026-10-29.

## Что известно
- DDrawCompat рисует DX7 через родной DirectDraw/D3D7 и D3D9 внутри; ReShade поддерживает D3D9/10/11/12, OpenGL, Vulkan, но не DirectDraw/D3D7.
- DLSS невозможен (нет векторов движения и буфера глубины, DX7).
- Путь, который описан в интернете для DX7-игр: dgVoodoo2 переводит DX1–7 в D3D11, ReShade ставится поверх как `dxgi.dll`, MSAA включает сам dgVoodoo.

## Что наблюдали
- При dgVoodoo2 заставки (видео через ddraw Blt) показываются, меню (D3D7-текстуры) нет.
- `ReShade.log` при dgVoodoo2: перехвачены `D3D11CreateDevice` и `D3D11CreateDeviceAndSwapChain`, feature level 11.0; swapchain ReShade не отмечает.
- Наши патчи, завязанные на DDrawCompat: `blt fix` (слот 0x14 вершинной таблицы первичной поверхности), `create window fix`/`rect fix`, `cursor_get`. Любой из них может ломать вывод с dgVoodoo2.

## Следующие гипотезы (по одной)
1. Настройки dgVoodoo2 (`OutputAPI`, `PresentationModel`, `ScalingMode`, 16-битный режим, `Resolution`) — картинка не попадает в окно в оконном режиме.
2. Вернуть DDrawCompat (`dgv.ps1 -Remove`) и искать сглаживание другим путём (профиль драйвера NVIDIA для ENGINE.exe). Если не решится: настройки dgVoodoo2 (`OutputAPI`, формат буфера, 16 бит), иначе вернуть DDrawCompat (`dgv.ps1 -Remove`) и искать сглаживание другим путём (профиль драйвера NVIDIA для ENGINE.exe).

## H26: маленькое окно со сглаживанием внутри игры (работает)
Цель: обычное окно (напр. 1280×720) при рендере выше окна (2560×1440), без DWM-миниатюры и «занавеса».
- Не подошли: alpha/region/окно за краем экрана/cloak (DWM-миниатюра требует полностью видимое непрозрачное окно); stretch-Blt на primary в DDrawCompat — без фильтра (nearest).
- Решение: `overlay.c` `hook()` перед флипом усредняет бэкбуфер на месте (box-фильтр, строка через буфер на стеке), `blt_fix` показывает угол кадра 1:1. Окно делают `create_fix`/`move_fix` размером `outw`×`outh` (`+0x300/+0x304`).
- Мышь: `cursor_get`/`cursor_fix` масштабируют `GetCursorPos`/`SetCursorPos`, `wndproc_fix` (`0x6000`, immediate по `0x417B69` — оконная процедура `0x417C80`) масштабирует координаты в сообщениях `0x200..0x209`. Без неё наведение работало, клики нет, камера в мире «бешено крутилась».
- Проверено по скриншотам и руками: меню, клики, мир. Ограничение масштаба высотой экрана убрано, `scale.ps1` удалён.
- Ловушки: ssh-сессия не видит окон (скрипты через `runit.ps1 -s <имя>`); старый `desk.png` легко принять за свежий; окно игры может быть под браузером (`fg.ps1`).

## Откат
`dgv.ps1 -Remove` возвращает DDrawCompat, `reshade.ps1 -Remove` убирает ReShade. Сейчас на Windows: DDrawCompat, ReShade и dgVoodoo2 сняты, профиль NVIDIA не импортирован: `-silentImport` по ssh (не администратор) завершается с кодом 0, но в экспорте `-exportCustomized` (51 профиль) engine.exe нет. Файлы лежат в `C:\Users\User\cof\npi` (`corsairs.nip`, 2x MSAA = 0x1000000E, ID 0x10D7162F), нужен ручной импорт через GUI.

### H26a: «картинка в картинке» при старте (исправлено)
- Причина: подмена `Blt` основной поверхности (`blt fix`) ставилась основным циклом только через ~7 с после старта; до неё первые кадры показывались как есть (угол большого рендера, с увеличением).
- Исправление: `BltFix()` вызывается в быстром цикле сразу после `Resume()` (`blt fix at start`, ~0,5 с); в `blt_fix` ветка растяжения кадра вне `hook()` больше не требует, чтобы ширина dst совпадала с рендером.
- Проверка: серия из 24 снимков после запуска (×3, окно 1920×1080) — угла/увеличенной картинки нет.
- Открыто: рябь на дальних объектах и «слоистость» при вращении камеры. Вероятные причины: 16-битный бэкбуфер игры (полосы на градиентах, усреднение их не лечит), mip-уровни текстур при большом рендере, fps ~27 при провалах 1%low ≈ 18.

## H27: интерфейс при суперсэмплинге (`install.ps1 -UiScale`)
Проблема: при рендере 5760×3240 (×3 от 1920×1080) меню мелкое, часть текста огромная.
- Причина 1: спрайты интерфейса (`RESOURCE\IMAGES\*.tga`) рисуются в своих пикселях текстуры, позиции `xo,yo` в INI — виртуальные 800×600. Фоны (`FONS`, 1024 px) растягиваются сами, кнопки и рамки — нет: они в 3,4–7,2 раза мельче нужного.
- Причина 2: `font:"name,N"` (без `,0`) масштабируется иначе, чем `font:"name,N,0"` (множитель из `fonts.ini`), поэтому часть текста получалась огромной.
- Причина 3 (баг `install.ps1`): `-FontScale` умножал и `rgb_npc_speech`/`rgb_our_speech` в `[DialogTerminal]`, цвета диалогов ломались; исправлено в regex (`(?!rgb_)`).
- Решение: `-UiScale` вместе с `-Supersample` увеличивает спрайты `BUTTONS FRAMES MENU SCROLLS STATUS RANSACK` в `Width/800` раз (Lanczos; у 16-бит цвет и альфа ресайзятся раздельно, иначе спрайты исчезают), дописывает `,0` ко всем `font:"name,N"` в `menu/map/town/status/ransack.ini`. Оригиналы лежат в `IMAGES\_orig` и `*.ini.orig`; без `-UiScale` и при `-Uninstall` возвращаются. Масштабирует PowerShell (C# `TgaScale` в `install.ps1`), Python не нужен; `tools/uiscale.py` — то же для Linux.
- В диалоге `[MessageBox]` у `EditText` размеры `dx,dy` задаются в пикселях рендера (×k), шрифт ×1,5.
- Ловушка: `_orig` нужно делать с настоящих оригиналов; если там уже лежат увеличенные файлы, второй проход даёт гигантские текстуры (картинка из растянутых полос).
- Проверка автотестом (`clickx/clicky` в `fix.ini` — позиция клика): главное меню, «Настройки» и диалог выхода пропорциональны.
- Открыто: в диалоге выхода кнопка «Да» перекрывает «Нет» (положение кнопок задаёт движок, `xo` в INI не действует); не проверены карта, город, окно корабля, «Создатели», загрузка/сохранение; один раз игра зависла после «Выход» (не повторилось).
- Окно настроек (`settings.ps1`): галочка «Крупный интерфейс при суперсэмплинге» (ключ `uiscale` в `fix.ini`, по умолчанию включена) передаёт `-UiScale`; работает при масштабе выше x1.
- Диалоги с персонажами (`[DialogTerminal]` в `fonts.ini`): при `-UiScale` шрифт получил множитель `Width/800` (110 вместо 52 при x2), и текст в панели диалога пропал. Движок сам умножает этот шрифт на высоту рендера/600, поэтому множитель для секции 1 (при `Height/960` текст получился вдвое крупнее нужного). Автотестом не проверено (нужен диалог в городе) — проверять руками.

### H27b. Верфь (`[ShipYard]` в town.ini)
- Подписи `s_ship*` (`txt:` с `xl/yl`) заданы в пикселях рендера, движок делит их пополам: без правки они сжимаются в левый верхний угол тёмным цветом на тёмном фоне. Лечение: x × 2k, y × 1,5k (y — чтобы строки совпали со столбцом значений `EditChar`, у которого шаг строк задаёт шрифт).
- Единицы `title3–11` (`xr`) движок ставит от правого края сам — их не трогать (с ×k уезжали вправо).
- `EditShipType/Name` (заголовки в плашках, `type:2`): `dx/dy` × k, иначе текст не виден.
- Всё делается в `Set-UiScale` из `town.ini.orig`. Проверено скриншотом 1920×1080.
- Не решено: мусор («Корпус/Очки») в левом верхнем углу экрана, мелкий `desc,14,0`, строка атласа шрифта посреди экрана.
